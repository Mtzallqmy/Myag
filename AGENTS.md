# Architecture rules

- Provider tokens live only as AES-GCM ciphertext in `provider_secrets` (service-role only, no RLS policies); `ai_providers` holds just a hint — so tokens are never browser-readable.
- Provider create/update/test and model upserts go through server functions in `src/lib/providers.functions.ts`; authenticated users have no INSERT grant on `ai_providers`/`ai_models` — so all writes pass SSRF validation and encryption.
- Every outbound call to a user-supplied URL must use `safeFetch` (`src/lib/server/outbound.server.ts`) — it enforces HTTPS, DNS-resolved public IPs, and per-hop redirect checks.
- Chat streaming is the `/api/chat` server route (SSE) that verifies the bearer token itself; server functions cannot stream raw responses.
- Model routing is the pure `selectCandidates` in `src/lib/ai/routing.ts`, bounded by `MAX_MODEL_ATTEMPTS`; no fallback after streaming starts — keeps retries finite and testable.
- All UI strings come from `src/lib/i18n/dictionaries.ts` (Arabic default, English mirror); code, URLs and model IDs render with `dir="ltr"`.
- The service worker is generated by vite-plugin-pwa and registered only via `src/lib/pwa.ts` guards — never in dev/preview/iframes.
- Browser reads use the RLS-scoped client via `src/lib/queries.ts` query options.
- Project file content lives in `project_chunks` (80-line chunks, the editable workspace); archives go to the private `project-archives` bucket under `<user_id>/` — no separate file store to sync.
- Archive extraction must go through `safeExtractZip` (central-directory pre-check for traversal, symlinks, bombs, limits) on both client and server.
- Agent/approval/git/MCP state changes happen only in server functions using the admin client after an RLS ownership check; authenticated users have SELECT-only grants on those tables.
- Every agent tool is declared in `src/lib/agent/policy.ts` (risk, min mode, approval, zod schema) and checked with `checkTool`; approvals execute only when `approvalExecutable` passes.
- Project code is never executed in this app; build/test go through `runtime.server.ts` (HMAC-signed) and must report UNAVAILABLE when not configured.
- External text (MCP output, GitHub issues/PRs) passes through `redactSecrets`/`redactValue` before display or model input.
- Plan limits, feature flags, kill switches and staff roles are defined only in `src/lib/policy/plans.ts` and enforced server-side via `src/lib/server/guards.server.ts` — so the browser cannot bypass them.
- Admin server functions in `src/lib/stage3.functions.ts` re-check roles with `staffCan` on every call; the `/admin` page is not a security boundary.
- Multi-agent runs use fixed role pipelines from `src/lib/agent/roles.ts` inside `runAgentJob`, capped by `MAX_JOB_STEPS` — no agent-to-agent chat.
- Memory rows are inserted only through `addMemory` after `validateMemoryCandidate` — raw model output never becomes memory.
